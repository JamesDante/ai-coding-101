## 学习目标

* 使用 JSON Schema 定义供 LLM 使用的工具
* 实现函数调用循环的请求-响应周期
* 通过 AI Agent 安全地执行本地 Shell 命令
* 将工具输出反馈到模型上下文中以生成最终答案

## 什么是工具调用？

当你与大语言模型 (LLM) 交互时，模型会根据其训练数据中的模式生成文本。然而，LLM 无法“伸手”触碰你的计算机。它无法检查你的文件系统、运行 Python 脚本或直接查询数据库。

工具调用（通常称为函数调用）是弥补这一差距的机制。在工具调用工作流中，模型本身并不执行代码。相反，它会识别出某个任务需要外部操作，并输出一个结构化的请求——通常是 JSON 格式——其中包含要使用的工具名称和必要的参数。

执行的责任在于你的应用程序（客户端）。你的代码解析 LLM 的请求，在本地机器上运行实际的函数，然后将结果发送回模型。这创建了一个循环，使 AI 能够观察其操作的结果并决定下一步行动。

## 定义工具 Schema

为了启用工具调用，你必须为 LLM 提供可用工具的蓝图。我们使用 JSON Schema 来描述这些工具。该 Schema 告诉模型工具的功能以及它期望的具体参数。

清晰的描述是定义中最关键的部分。LLM 使用 `description` 字段来决定某个工具是否适用于当前的提示词（prompt）。如果你的描述含糊不清，模型可能会无法触发工具或提供格式错误的参数。

```json title="tool_definition.json"
{
  "name": "run_script",
  "description": "执行本地 Shell 命令或 Python 脚本并返回输出。",
  "input_schema": {
    "type": "object",
    "properties": {
      "command": {
        "type": "string",
        "description": "要执行的完整 Shell 命令，例如 'ls -la' 或 'python3 script.py'。"
      },
      "timeout": {
        "type": "integer",
        "description": "允许命令运行的最大秒数。",
        "default": 30
      }
    },
    "required": ["command"]
  }
}
```

:::tip
在编写工具描述时，请使用祈使句（例如“使用此工具来获取...”），并明确说明输入参数的预期格式。
:::

## 实现工具循环

“循环”是 AI Agent 的引擎。它是一个持续的周期，负责管理对话历史，并处理用户输入、模型推理与工具执行之间的转换。

该过程遵循以下步骤：
1. 将用户提示词和工具定义发送给 LLM。
2. 检查模型的响应。如果 `stop_reason` 指示为 `tool_use`，则提取工具名称和参数。
3. 使用这些参数执行相应的本地函数。
4. 将模型的工具请求和函数的输出都追加到对话历史中。
5. 将更新后的历史记录发送回 LLM。

```python title="agent_loop.py"
import json

def run_agent_loop(client, model, messages, tools):
    while True:
        # 1. 向 LLM 发送请求
        response = client.messages.create(
            model=model,
            tools=tools,
            messages=messages
        )
        
        # 将助手的响应添加到历史记录中
        messages.append(response.content[0])

        # 2. 检查模型是否想要使用工具
        if not response.stop_reason == "tool_use":
            break

        # 3. 处理工具请求
        for content in response.content:
            if content.type == "tool_use":
                tool_id = content.id
                tool_name = content.name
                arguments = json.loads(content.input)

                print(f"[*] 正在执行工具：{tool_name}，参数为：{arguments}")
                
                # 执行实际的本地逻辑
                result = execute_local_tool(tool_name, arguments)

                # 4. 将结果反馈到历史记录中
                messages.append({
                    "role": "user",
                    "content": [
                        {
                            "type": "tool_result",
                            "tool_use_id": tool_id,
            "content": result
                        }
                    ]
                })

    return messages[-1].content # 返回最终的文本响应
```

## 构建本地脚本执行器

工具的一个实际实现通常涉及与操作系统的交互。我们可以使用 Python 的 `subprocess` 模块来捕获 Shell 命令的输出。通过同时捕获 `stdout`（标准输出）和 `stderr`（错误输出），我们为 LLM 提供完整的可见性，使其能够了解命令成功还是失败。

```python title="executor.py"
import subprocess

def execute_local_tool(name, arguments):
    if name == "run_script":
        command = arguments.get("command")
        try:
            # 运行命令并捕获输出
            process = subprocess.run(
                command,
                shell=True,
                capture_output=True,
                text=True,
                timeout=arguments.get("timeout", 30)
            )
            
            # 合并 stdout 和 stderr，以便让 LLM 看到完整信息
            output = process.stdout
            if process.stderr:
                output += f"\n错误信息:\n{process.stderr}"
            
            return output if output else "命令执行成功（无输出）。"
            
        except subprocess.TimeoutExpired:
            return "错误：命令超时。"
        except Exception as e:
            return f"执行命令出错：{str(e)}"
    
    return "错误：未找到该工具。"
```

:::warning
切勿允许 LLM 在没有严格沙箱环境或人工介入审批的情况下，在生产系统上执行任意 Shell 命令，因为这会造成严重的安全漏洞。
:::

## 错误处理与自我修正

工具调用最强大的功能之一就是“自我修正”。由于来自本地环境的错误信息会被反馈到模型的上下文中，LLM 可以清楚地看到命令失败的原因。

如果一个 Python 脚本因 `Traceback` 而崩溃，LLM 会收到该 traceback 作为 `tool_result`。随后，模型可以分析错误，意识到它传递了错误的文件路径或格式错误的参数，并尝试使用修正后的参数再次调用工具。

```python title="error_handling_demo.py"
# 演示循环如何处理失败情况的示例
messages = [
    {"role": "user", "content": "运行一个脚本来检查 'config.json' 是否存在。"}
]

# 如果工具返回："错误：FileNotFoundError: [Errno 2] No such file or directory: 'config.json'"
# LLM 在历史记录中看到此信息并可以响应：
# "我尝试检查 config.json 但未找到。让我尝试列出当前目录看看。"
```

通过将错误视为另一种形式的输入，你将一个静态脚本转变为一个能够应对复杂、不可预测环境的自适应 Agent。

## 小结

* 工具调用允许 LLM 请求由客户端在本地执行的操作。
* JSON Schema 用于定义工具的接口、名称和参数。
* 需要一个执行循环来管理模型与本地函数之间的往返交互。
* 捕获 `stderr` 对于使 LLM 在命令失败后能够进行自我修正至关重要。
