Build an AI Chat App

Learning Objectives​

  • Implement a streaming response interface to reduce perceived latency.
  • Develop a conversation memory system to maintain multi-turn context.
  • Integrate a Retrieval Augmented Generation (RAG) pipeline for grounding responses in external data.
  • Configure the Claude API for high-performance chat interactions.

System Architecture: The Chat Pipeline​

Building a production-grade AI application requires more than just sending a prompt to an LLM. A robust chat pipeline orchestrates several moving parts before the user ever sees a response.

The architecture follows a linear pipeline of enrichment steps:

  1. Ingestion: The user sends a query via a client-side interface.
  2. Retrieval (RAG): The system queries a vector database to find relevant document snippets related to the user's query.
  3. Context Augmentation: The system retrieves recent conversation history from a memory buffer.
  4. Prompt Construction: The system assembles a final prompt containing the System Instructions, retrieved Context, Conversation History, and the new User Query.
  5. Inference & Streaming: The request is sent to the Claude API. As the LLM generates tokens, the server streams these chunks back to the client using Server-Sent Events (SSE).

Implementing Real-time Streaming​

To prevent users from staring at a loading spinner, we use streaming. This allows the UI to render text as it is being generated, significantly improving the perceived speed of the application.

api/chat/route.ts
import { Anthropic } from '@anthropic-ai/sdk';

const anthropic = new Anthropic({
  apiKey: process.env.ANTHROPIC_API_KEY,
});

export async function POST(req: Request) {
  const { messages } = await req.json();

  // Create a ReadableStream to pipe the LLM response to the client
  const stream = await anthorpics.messages.stream({
    model: 'claude-3-5-sonnet-20240620',
    max_tokens: 1024,
    messages: messages,
  });

  // Transform the Anthropic stream into a standard Web ReadableStream
  const readableStream = new ReadableStream({
    async start(controller) {
      for await (const event of stream.stream) {
        if (event.type === 'content_block_delta') {
          const text = event.delta.text;
          controller.enqueue(new TextEncoder().encode(`data: ${JSON.stringify({ text })}\n\n`));
        }
      }
      controller.enqueue(new TextEncoder().encode('data: [DONE]\n\n'));
      controller.close();
    },
  });

  return new Response(readableStream, {
    headers: { 'Content-Type': 'text/event-stream' },
  });
}

Managing Conversation Memory​

LLMs are stateless; they do not remember previous interactions unless you explicitly provide them in the prompt. We implement a "Sliding Window" memory system to keep track of recent messages while staying within the model's token limit.

lib/memory.ts
export interface Message {
  role: 'user' | 'assistant' | 'system';
  content: string;
}

export class ChatHistoryManager {
  private history: Message[] = [];
  private readonly maxTokens: number = 4000;

  constructor(initialHistory: Message[]) {
    this.history = initialHistory;
  }

  public addMessage(message: Message) {
    this.history.push(message);
    this.pruneHistory();
  }

  private pruneHistory() {
    // Simple implementation: remove oldest messages if history gets too long
    // In production, use a library like 'tiktoken' to count actual tokens
    let currentTokenEstimate = this.history.length * 100; 

    while (currentTokenEstimate > this.maxTokens && this.history.length > 2) {
      this.history.shift(); // Remove the oldest message
      currentTokenEstimate -= 100;
    }
  }

  public getMessages(): Message[] {
    return this.history;
  }
}
warning

Be careful with unbounded memory growth; always implement a pruning strategy or summary-based mechanism to avoid hitting the model's maximum context window.

Adding RAG Capabilities​

Retrieval Augmented Generation (RAG) allows the AI to answer questions about data it wasn't trained on, such as your company's private documentation. We retrieve relevant snippets and inject them into a "Context" block within the prompt.

lib/rag.ts
export async function getContext(query: string): Promise<string> {
  // In a real app, this would query a Vector Database like Pinecone or Supabase
  const mockRetrievedDocs = [
    { text: "Remote work policy: Employees can work from home 3 days a week." },
    { text: "Office hours are 9 AM to 5 PM EST." }
  ];

  // Simulate similarity search
  const relevantContext = mockRetrievedDocs
    .filter(doc => query.toLowerCase().includes('work') || query.toLowerCase().includes('office'))
    .map(doc => doc.text)
    .join('\n');

  return relevantContext ? `CONTEXT:\n${relevantContext}` : "";
}
tip

To improve RAG quality, try adding 'citations' to your system prompt, instructing the LLM to reference specific documents when answering.

End-to-End Example: Full Chat Cycle​

This section demonstrates how all components—Streaming, Memory, and RAG—integrate into a single request handler.

End-to-End: Full Chat Cycle
User: "What is our remote work policy?"

Step 1 → System receives query and triggers RAG retrieval.
Step 2 → RAG engine finds snippet: "Employees can work from home 3 days a week."
Step 3 → Memory Manager retrieves the last 5 messages from the session.
Step 4 → The system constructs the final prompt:
         [System Instructions] + [Retrieved Context] + [Chat History] + [User Query]
Step 5 → The request is sent to the Claude API with 'stream: true'.
Step 6 → The API sends back chunks: "Employees", " can", " work", " from", " home".
Final:  The user sees the response appearing in real-time on their screen.
api/chat/integrated-handler.ts
import { Anthropic } from '@anthropic-ai/sdk';
import { ChatHistoryManager } from '../../lib/memory';
import { getContext } from '../../lib/rag';

const anthropic = new Anthropic({ apiKey: process.env.ANTHROPIC_API_KEY });

export async function handleChatRequest(userQuery: string, previousMessages: any[]) {
  // 1. Initialize Memory
  const memoryManager = new ChatHistoryManager(previousMessages);
  
  // 2. Perform RAG Retrieval
  const context = await getContext(userQuery);

  // 3. Construct Augmented Prompt
  const augmentedMessages = [
    { role: 'system', content: `You are a helpful assistant. Use this context to answer: ${context}` },
    ...memoryManager.getMessages(),
    { role: 'user', content: userQuery }
  ];

  // 4. Execute Streaming Request
  const stream = await anthropic.messages.stream({
    model: 'claude-3-5-sonnet-20240620',
    max_tokens: 1024,
    messages: augmentedMessages,
  });

  return stream;
}

Exercise​

Create a new utility function called summarizeHistory. This function should take the ChatHistoryManager's message array and, if the message count exceeds 10, use an LLM call to generate a single-paragraph summary of the conversation. Replace the old messages with this summary to save tokens.

Summary​

  • Streaming reduces perceived latency by delivering text chunks as they are generated.
  • Memory Management is essential for maintaining context while preventing token overflow.
  • RAG allows you to ground AI responses in external, private datasets.
  • Orchestration involves a pipeline of retrieval, augmentation, and inference.
