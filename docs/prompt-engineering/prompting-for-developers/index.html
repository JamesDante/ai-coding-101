Prompting for Developers

Learning Objectives​

  • Define a specific professional persona for the AI to improve output quality
  • Structure prompts using the Role-Task-Constraint framework
  • Apply technical constraints to minimize hallucinations and ensure compatibility
  • Iteratively refine AI-generated code through targeted feedback loops

The Anatomy of a Developer Prompt​

Generic prompts often produce generic, unusable code. If you ask an LLM (Claude, GPT-4o, Gemini) to "write a script to parse JSON," you might receive a simple snippet that lacks error handling, logging, or proper type definitions. To move from hobbyist scripts to production-ready code, you should use the Role-Task-Constraint (RTC) framework.

The RTC framework provides the structure necessary for professional software engineering. By defining who the AI is, what it must do, and what it must avoid, you significantly reduce the need for manual corrections.

Prompt Comparison
// Naive Prompt
Write a Python script to scrape a website.

// Structured Developer Prompt (RTC)
Role: Senior Web Scraping Engineer.
Task: Create a Python script using BeautifulSoup to extract product names and prices from an e-commerce URL.
Constraints: Use the requests library, implement error handling for 404 errors, and output the data as a CSV file.

Defining the Persona (The Role)​

Assigning a specific role shifts the model's internal priorities. When you assign a persona, you are not just giving it a title; you are instructing the model to prioritize certain patterns, such as security, scalability, or performance.

For example, changing the role from a general "Coder" to a "Security Auditor" changes the focus of the output from functional logic to vulnerability detection and input sanitization.

Role Impact Comparison
// Role: Junior Developer
Task: Write a function to handle user passwords.
Result: Focuses on basic string manipulation and storage.

// Role: Security Engineer
Task: Write a function to handle user passwords.
Result: Focuses on salting, hashing (Argon2/bcrypt), and preventing timing attacks.

Precision in Task Definition​

Vague tasks lead to "hallucinations," where the AI assumes data structures that do not exist. To prevent this, define your inputs and outputs with extreme precision. Use explicit types, expected keys, and return values to ensure the generated code integrates seamlessly into your existing codebase.

Type-Safe Prompting
Role: TypeScript Expert.
Task: Create a function called `processUser` that accepts a User object.
Input Interface:
interface User {
  id: string;
  email: string;
  age: number;
}
Output: Return a Promise<string> containing the user's formatted profile summary.

Applying Hard Constraints​

Constraints are your primary tool for enforcing coding standards and architectural limitations. Use constraints to specify library versions, prevent the use of deprecated methods, or forbid external dependencies that would bloat your package size.

Constraint Enforcement
Role: Python Backend Developer.
Task: Write a function to calculate the moving average of a list of integers.
Constraints:
- Use only the standard library (no NumPy).
- Ensure compatibility with Python 3.8+.
- Follow PEP8 style guidelines.
- Implement type hints for all parameters and return values.
tip

When applying constraints, list them as a bulleted list. LLMs process structured lists more reliably than long paragraphs of requirements.

The Iterative Refinement Loop​

Treat the first output from the AI as a draft rather than a finished product. Professional prompting involves an iterative loop where you provide targeted feedback to address edge cases or style violations discovered during testing.

Instead of restarting the conversation, use follow-up prompts to refine specific logic. This preserves the context of the existing code while narrowing the scope of the fix.

Refinement Sequence
// Prompt 1 (Initial Task)
Role: Python Developer. Task: Write a function to divide two numbers.

// Prompt 2 (Addressing Edge Case)
The code works, but it crashes if the second number is zero. Update the function to raise a ValueError when the divisor is 0.

// Prompt 3 (Refining Style)
Now, update the function to use type hints and add a docstring in Google format.
warning

Never assume AI-generated code is secure by default. Always perform a manual security review or run the code through a static analysis tool before merging to production.

Exercise​

Create a prompt using the Role-Task-Constraint framework to generate a Python function that calculates the Fibonacci sequence up to $n$ terms. Your prompt must include:

  1. A specific professional persona.
  2. A constraint that forbids the use of recursion (to prevent stack overflow).
  3. A constraint requiring the output to be a list of integers.

Summary​

  • Use the Role-Task-Constraint (RTC) framework to create structured, professional prompts.
  • Assigning a specific Persona shifts the AI's priority toward best practices like security or performance.
  • Define explicit inputs and outputs using interfaces or schemas to ensure type safety.
  • Apply Hard Constraints to enforce library versions and coding standards.
  • Use an Iterative Refinement Loop to fix bugs and edge cases without losing context.
