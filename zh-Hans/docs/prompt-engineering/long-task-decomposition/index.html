长任务分解

学习目标​

  • 定义"原子化"实现任务的标准
  • 基于技术依赖关系为复杂功能创建顺序路线图
  • 将 AI 作为技术架构师来生成分解列表
  • 实现验证循环，确保在继续下一步之前每一步都是正确的

单体式 Prompt 的失败​

当你要求 AI "构建一个完整的用户身份验证系统"时，你是在为失败埋下伏笔。这种被称为单体式提示（Monolithic Prompting）的方法通常会导致几个常见问题。

大型请求会导致幻觉（hallucinations），即 AI 虚构不存在的库或 API。你还会经常看到代码缺失，LLM 会插入类似 // ... 此处省略逻辑 的注释，而不是提供完整的实现。最后，复杂的 Prompt 会增加逻辑错误风险，且后期难以调试。

定义原子化任务​

为了获得可靠的结果，你必须使用"原子化任务（atomic tasks）"。原子化任务是遵循单一职责原则且可以独立进行完整测试的工作单元。

不要要求构建整个功能，而是将其拆分为只做一件事情的片段。

对比：单体式 vs. 原子化
### 单体式 Prompt（差）
"构建一个完整的计费系统，集成 Stripe，包括数据库模型、API 端点和前端仪表板。"

### 原子化 Prompt（好）
1. "为 `Subscription`（订阅）模型创建 Prisma Schema。"
2. "实现一个处理 Stripe Webhook 的 Node.js 控制器。"
3. "创建一个展示用户当前套餐状态的 React 组件。"
注意

避免"过度分解"。如果任务太小（例如，仅创建一个变量），AI 可能会丢失编写该代码的宏观上下文，导致逻辑碎片化。

映射技术依赖关系​

执行任务的顺序至关重要。如果你在底层 API 存在之前就尝试构建前端组件，你将会遇到迫使你不断进行重组（refactoring）的错误。

请遵循以下标准的分解顺序：

  1. 数据库 Schema：首先定义你的数据结构。
  2. 后端逻辑/API：构建操作这些数据的服务和端点（endpoints）。
  3. 前端集成：创建 UI 组件并将其连接到 API。
  4. 边缘情况处理：添加校验、错误状态和加载指示器。
实现路线图：用户订阅
1. 在 PostgreSQL 中定义 `Subscription` 和 `Plan` 表。
2. 创建与 Stripe 交互的 Express 路由 `/api/subscribe`。
3. 构建 React `SubscriptionCard` 组件。
4. 为信用卡过期情况实现错误处理。

将 AI 作为架构师​

你不必亲自动手完成所有的分解工作。你可以使用"元提示（Meta-Prompt）"将 LLM 变成技术负责人（Technical Lead）。不要直接索要代码，而是要求 AI 担任架构师的角色，并生成一份实现步骤的清单。

架构师元提示
"我想实现 [功能名称]。在编写任何代码之前，请以高级技术负责人的身份，分析需求并提供一份有序的原子化实现任务列表。每个任务必须足够小，能在单个 Prompt 中完成，并注明其技术依赖关系。"

执行与验证循环​

分解中最关键的部分是验证循环。在确认当前任务完美运行之前，绝不要进入下一个任务。

工作流遵循严格的循环：

  1. 执行：运行原子化任务的 Prompt。
  2. 验证：运行测试或手动检查输出。
  3. 反馈：如果发生错误，将错误信息反馈给 AI。
  4. 继续：只有在当前任务通过验证后，才进入下一个任务。

跳过这一步会导致"错误累进（error compounding）"，即第一步中的一个小错误到第五步时会变成一个巨大的、无法修复的 Bug。

终端
# 第 1 步：运行新创建的测试
npm test tests/webhook.test.ts

# 第 2 步：如果失败，复制错误并粘贴给 AI
# Error: TypeError: Cannot read property 'id' of undefined
提示

在单独的 Markdown 文件中维护一个"进度日志（Progress Log）"。将此日志粘贴到每个新的 Prompt 中，这样 AI 就能确切地知道分解过程中的哪些步骤已完成，哪些仍待处理。

练习​

选取一个你目前正在处理的复杂功能（例如，"用户头像上传"），并按照依赖映射规则将其分解为至少四个原子化任务：数据库 $\rightarrow$ 后端 $\rightarrow$ 前端 $\rightarrow$ 边缘情况。请以编号列表的形式写出这些任务。

小结​

  • 单体式 Prompt 会导致幻觉、代码缺失和逻辑错误。
  • 原子化任务是易于测试的单一职责工作单元。
  • 始终遵循依赖链：Schema $\rightarrow$ API $\rightarrow$ UI。
  • 使用元提示让 AI 协助你构建任务列表。
  • 实现验证循环以防止错误累进。
