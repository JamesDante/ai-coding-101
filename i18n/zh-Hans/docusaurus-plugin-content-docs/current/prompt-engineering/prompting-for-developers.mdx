## 学习目标

- 为 AI 定义特定的专业角色 (Persona) 以提升输出质量
- 使用 角色-任务-约束 (RTC) 框架构建提示词
- 应用技术约束以减少幻觉 (Hallucination) 并确保兼容性
- 通过针对性的反馈循环迭代优化 AI 生成的代码

## 开发者 Prompt 的构造

通用的提示词往往会产生通用且无法使用的代码。如果你要求 LLM（Claude、GPT-4o、Gemini 等）"写一个解析 JSON 的脚本"，你可能会得到一段简单的代码片段，其中缺乏错误处理、日志记录或正确的类型定义。为了从业余脚本转向生产级代码，你应该使用 角色-任务-约束 (RTC) 框架。

RTC 框架为专业的软件工程提供了必要的结构。通过定义 AI 是谁、它必须做什么以及它必须避免什么，你可以显著减少手动修正的需求。

```text title="Prompt 对比"
// 简单提示词
写一个 Python 脚本来抓取网站。

// 结构化开发者 Prompt (RTC)
角色：高级网页抓取工程师。
任务：使用 BeautifulSoup 创建一个 Python 脚本，从电商 URL 中提取产品名称和价格。
约束：使用 requests 库，为 404 错误实现错误处理，并将数据输出为 CSV 文件。
```

## 定义角色 (Persona)

分配特定的角色会改变模型的内部优先级。当你分配一个 Persona 时，你不仅仅是在给它一个头衔；你是在指示模型优先考虑某些模式，例如安全性、可扩展性或性能。

例如，将角色从通用的"程序员"更改为"安全审计员"，会将输出的重点从功能逻辑转向漏洞检测和输入清洗。

```text title="角色影响对比"
// 角色：初级开发人员
任务：编写一个处理用户密码的函数。
结果：专注于基本的字符串操作和存储。

// 角色：安全工程师
任务：编写一个处理用户密码的函数。
结果：专注于加盐、哈希 (Argon2/bcrypt) 以及防止计时攻击。
```

## 任务定义的精确性

模糊的任务会导致"幻觉 (Hallucinations)"，即 AI 假设了并不存在的数据结构。为了防止这种情况，请极其精确地定义你的输入和输出。使用明确的类型、预期的键 (Keys) 和返回值，以确保生成的代码能够无缝集成到你现有的代码库中。

```typescript title="类型安全提示词"
角色：TypeScript 专家。
任务：创建一个名为 `processUser` 的函数，接受一个 User 对象。
输入接口：
interface User {
  id: string;
  email: string;
  age: number;
}
输出：返回一个 Promise<string>，包含用户的格式化个人信息摘要。
```

## 应用硬约束

约束是你强制执行编码标准和架构限制的主要工具。使用约束来指定库的版本、防止使用已弃用的方法，或者禁止会增加包体积的外部依赖。

```python title="约束执行"
角色：Python 后端开发者。
任务：编写一个计算整数列表移动平均值的函数。
约束：
- 仅使用标准库（不允许使用 NumPy）。
- 确保与 Python 3.8+ 兼容。
- 遵循 PEP8 代码风格规范。
- 为所有参数和返回值实现类型提示。
```

:::tip
在应用约束时，请使用项目符号列表。LLM 处理结构化列表的可靠性远高于处理长篇大论的需求描述。
:::

## 迭代优化循环

将 AI 的第一次输出视为草稿，而非最终产品。专业的 Prompting 涉及一个迭代循环，你通过提供针对性的反馈，来解决在测试过程中发现的边界情况或风格违规问题。

与其重新开始对话，不如使用后续提示词来优化特定的逻辑。这样可以在缩小修复范围的同时，保留现有代码的上下文。

```text title="优化序列"
// 提示词 1（初始任务）
角色：Python 开发者。任务：编写一个对两个数字进行除法运算的函数。

// 提示词 2（处理边界情况）
代码可以运行，但当第二个数字为零时会崩溃。请更新函数，在除数为 0 时抛出 ValueError。

// 提示词 3（优化风格）
现在，更新函数以使用类型提示，并添加 Google 格式的文档字符串。
```

:::warning
永远不要假设 AI 生成的代码默认就是安全的。在合并到生产环境之前，务必进行人工安全审查或使用静态分析工具运行代码。
:::

## 练习

请使用 角色-任务-约束 框架编写一个提示词，生成一个能够计算前 $n$ 项斐波那契数列 (Fibonacci sequence) 的 Python 函数。你的提示词必须包含：
1. 一个特定的专业角色。
2. 一个禁止使用递归的约束（以防止栈溢出）。
3. 一个要求输出结果为整数列表的约束。

## 小结

- 使用 角色-任务-约束 (RTC) 框架来创建结构化、专业的提示词。
- 分配特定的角色可以将 AI 的优先级转向安全性或性能等最佳实践。
- 使用接口 (Interfaces) 或 Schema 来定义明确的输入和输出，以确保类型安全。
- 应用硬约束来强制执行库版本和编码标准。
- 使用迭代优化循环在不丢失上下文的情况下修复 Bug 和边界情况。
